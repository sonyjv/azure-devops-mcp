How it works

From requirement to test case, without leaving chat.

This page explains how VS Code, GitHub Copilot, and the Azure DevOps MCP Server work together to turn a requirement already sitting in Azure DevOps into reviewed, published test cases — with a real person approving the work before anything is saved. No coding involved.

The middle piece — the MCP Server — doesn't store anything of its own and has no login of its own. It simply passes your request along and hands back the result, signed in as you. It can only do what you're already allowed to do in Azure DevOps by hand.

Before you start

A short, one-time setup — someone technical usually does this once per project.

  1. Install VS Code and Node.js — the two free programs everything else runs on top of.
  2. Add a small connection file to the project, pointing at your Azure DevOps organization (or, for an in-house server, its address).
  3. Switch on the bridge from VS Code's tool panel, then open Copilot Chat and switch it to Agent mode.
  4. Sign in with the same account you already use for Azure DevOps. From this point on, Copilot can only see and touch what that account can.

You only do this once per project — everything from here on is just typing in chat.

The workflow

Four steps, the same way a QA engineer would do this by hand — except Copilot does the typing, and you do the approving.

1
Pick a requirement

Tell Copilot which requirement to look at, by name, ID, or a short description. It opens the same work item you'd otherwise open by hand in Azure DevOps — same title, same description, same acceptance criteria.

You, in Copilot ChatShow me requirement US-4213 in the Contoso project.
Under the hood
Copilot calls the server's wit_work_item (or wit_query to search first) tool, which reads the work item straight from Azure DevOps' own API — nothing cached, nothing guessed.
2
Copilot drafts test cases

Copilot reads the requirement's description and acceptance criteria, then writes a first draft of test cases covering it. This part is Copilot's own writing — a proposal, not something pulled from Azure DevOps.

You, in Copilot ChatDraft test cases for this, covering the happy path and the edge cases.
Copilot's draft (not saved anywhere yet)
  • Reset link is emailed within 60 seconds of a valid request
  • Expired reset link shows a clear "link expired" message
  • Reset request for an unregistered email shows no account-existence hint
Under the hood
No Azure DevOps tool is called here at all — this step is Copilot reasoning over the text it already retrieved in step 1.
3
You review

Read the draft the way you'd review a colleague's work. Nothing has touched Azure DevOps yet — this is still just a conversation. Ask for changes, add a missing case, or drop one you don't need.

Nothing is saved until you explicitly ask for it in the next step. This is the checkpoint.
4
Publish to Azure DevOps

Once you're happy with the draft, ask Copilot to save it. It creates real Test Case work items in Azure DevOps and links each one back to the requirement it was written for — the same link a person would draw by hand.

You, in Copilot ChatCreate these as test cases under test plan "Sprint 12 Regression" and link them to US-4213.
In Azure DevOps Three new Test Case work items appear under Sprint 12 Regression, each showing a "Tested By" link back to US-4213 — visible to your whole team, not just you.
Under the hood
Copilot calls testplan_test_case_write (action: create) to write each test case, then wit_work_item_link_write to add the "Tested By" relationship back to the requirement, and testplan_test_suite_write if it needs to place them in a specific suite.

Trust & safety

The three questions people usually ask first.

Can it change things without asking me?
No. Nothing is written to Azure DevOps until you explicitly ask for it — that's step 4, never earlier.
Can it see things I'm not allowed to see?
No. It signs in as you, so it only sees and touches what your own Azure DevOps account already can.
Do I need to know how to code?
No. Every step is a plain-English sentence typed into a chat window — nothing else.

A quick note

This isn't Microsoft's official Azure DevOps MCP Server — it's a fork of it. Microsoft's version, and its newer hosted option, only connect to Azure DevOps Services in the cloud. This fork adds the ability to connect to an Azure DevOps Server running on your own company's network — sometimes called TFS — which plenty of organizations still run instead of, or alongside, the cloud version. Everything else on this page behaves identically either way: what Copilot can see, how review works, what gets published.
